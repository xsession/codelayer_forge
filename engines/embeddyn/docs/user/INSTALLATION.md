# Installation and bootstrap

Embeddyn uses a west-like bootstrap manager so source dependencies and Python dependencies can be managed reproducibly. The repository-level manifest is `embeddyn.yml`; exact resolved source state is stored in `embeddyn.lock.json`.

## Requirements

The bootstrap script requires a suitable Python 3 installation and Git for normal source synchronization. The manifest currently declares Python **3.9 or newer**. Full simulation/tool builds additionally require common compiler/build utilities; `bootstrap.py doctor` and `bootstrap.py system-deps` expose the current requirements.

## Fast installation

### Linux / macOS-like shell

```bash
python3 bootstrap.py bootstrap --profile studio
. ./.embeddyn/env.sh
embeddyn studio doctor
```

For the complete tool/source profile:

```bash
python3 bootstrap.py bootstrap --profile full
. ./.embeddyn/env.sh
```

On supported Debian/Ubuntu environments, bootstrap can also request host packages and the complete engineering workspace:

```bash
python3 bootstrap.py bootstrap --profile full --install-system --workspace
. ./.embeddyn/env.sh
```

### Windows PowerShell

Use the repository launcher rather than duplicating command logic:

```powershell
.\bootstrap.ps1 bootstrap --profile studio
```

The CMD launcher is `bootstrap.cmd`.

## Profiles

The source of truth is the `profiles` section in `embeddyn.yml`.

- `core`: core source/resource group and base Python package.
- `studio`: core + FastAPI/uvicorn/Pydantic/Numpy/firmware-analysis dependencies.
- `rf`: core + locked openEMS source project + Studio/RF Python dependencies.
- `full`: core + external engineering tools + RF tools + Studio/storage/RF Python extras.
- `dev`: same broad source set as full plus test dependencies.

## Understanding `sync`, `update`, `lock`, and `freeze`

The most important rule is that **normal synchronization should reproduce the lock, not silently move dependencies**.

```text
embeddyn.yml          desired project URLs/groups/update refs
       |
       | explicit update
       v
embeddyn.lock.json    exact commits or bundled-tree SHA-256 fingerprints
       |
       | sync/bootstrap
       v
working dependency trees
```

Common commands:

```bash
python3 bootstrap.py status
python3 bootstrap.py list
python3 bootstrap.py sync --profile full
python3 bootstrap.py update --profile full
python3 bootstrap.py lock
python3 bootstrap.py freeze
python3 bootstrap.py doctor --profile full
```

- **`sync`** materializes exact locked revisions.
- **`update`** is the intentional operation that advances selected dependencies to manifest refs and updates the lock.
- **`lock`** records current source revisions/content.
- **`freeze`** freezes source state and installed Python versions.
- Dirty Git worktrees are protected rather than overwritten implicitly.
- Bundled source trees without Git metadata are verified by content fingerprints.

See [Bootstrap and dependency versioning](../BOOTSTRAP_AND_DEPENDENCY_VERSIONING.md) for the full policy.

## Environment and important paths

Typical repository/workspace paths:

| Path | Purpose |
|---|---|
| `.venv/` | Bootstrap-managed Python virtual environment. |
| `.embeddyn/` | Runtime/setup state, generated environment helper, run metadata depending on workflow. |
| `workspace/` | Default engineering workspace and local library root. |
| `workspace/embeddyn-resources/` | Component specification/resource checkout. |
| `externals/` | Bundled or synchronized external engineering projects. |
| `embeddyn.lock.json` | Frozen source dependency state. |
| `requirements.lock.txt` | Frozen Python environment when generated by `freeze`. |

Studio uses a platform-specific user data directory by default. Override it with `--data-dir` or `EMBEDDYN_LOCAL_DATA_DIR` when you want a project-local or portable setup.

## Offline operation

Embeddyn is designed so existing locked/bundled resources can continue to be used without network access. However, a first installation cannot fetch missing Git projects, Python packages, or external simulator packages without a package/source cache. For an air-gapped environment:

1. Populate the repository and locked external projects on a connected machine.
2. Freeze/capture the Python environment or use an internal package index/wheelhouse.
3. Copy the complete repository/workspace to the offline machine.
4. Use `bootstrap.py status` before `sync` to confirm what is already materialized.
5. Keep the local component library in offline mode (its default configuration).

## Remote Studio access

Studio binds to loopback by default. A non-loopback bind is refused unless remote mode is explicitly enabled. Remote mode requires a non-empty bearer token; when one is not provided through the environment, a token is generated in the Studio data directory with restrictive file permissions where supported.

Example:

```bash
embeddyn studio run --host 0.0.0.0 --allow-remote --no-open-browser
```

Treat the printed/generated token as a secret. Prefer an SSH/VPN tunnel or trusted private network; Local Studio is not intended to replace a hardened internet-facing multi-user service.

## Verify the installation

Use these progressively stronger checks:

```bash
python3 bootstrap.py doctor --profile studio
embeddyn studio doctor
embeddyn rf status
embeddyn mechatronics doctor
```

Not every external simulator must be installed for every workflow. Missing optional tools should be interpreted in context: mock simulation and local analysis remain useful without Renode/Webots/SPICE/openEMS native binaries.
